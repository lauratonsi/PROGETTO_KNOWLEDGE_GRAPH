Query SPARQL sul Knowledge Graph

Dieci query che interrogano il KG bolognese. Le query 1–6 coprono le keyword obbligatorie (OPTIONAL, DISTINCT, UNION, FILTER, REGEX, LIMIT, ORDER BY). Le query 7–10 sfruttano le nuove proprietà topografiche e semantiche: ex:quartiere, ex:dataIstituzione, ex:macroCategoriaOccupazionale, ex:datiAnagrafici.

Interrogazione interattiva

Scrivi o modifica una query SPARQL ed eseguila direttamente nel browser sul Knowledge Graph di Bologna. Il file bologna_KG_corretto.ttl viene caricato in memoria tramite Oxigraph, un motore SPARQL 1.1 compilato in WebAssembly.

Nota: al primo click il browser scarica il motore WebAssembly e il file RDF (~1 MB). Le query successive sono istantanee perché il KG rimane in memoria.

Il Knowledge Graph è disponibile come file Turtle nel repository: bologna_KG_corretto.ttl (27.251 righe, ~21.000 triple dopo l'arricchimento). Per eseguire le query localmente: python run_queries.py (usa rdflib).

Query 1 — Conteggio strade per genere

Domanda: quante strade di Bologna sono dedicate a uomini e quante a donne? Questa è la risposta principale al gender gap.
Keyword: DISTINCT, COUNT, GROUP BY, ORDER BY

## Query 1 — Conteggio strade per genere
## Keywords: DISTINCT, COUNT, GROUP BY, ORDER BY
##
## Domanda: quante strade di Bologna sono dedicate a uomini
## e quante a donne? Questa è la risposta principale al gender gap.

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>

SELECT ?genere (COUNT(DISTINCT ?via) AS ?numero_strade)
WHERE {
  ?via a clv:Street ;
       clv:isDedicatedTo ?persona .
  ?persona a cpv:Person ;
           cpv:sex ?genere .
}
GROUP BY ?genere
ORDER BY DESC(?numero_strade)

Risultati:

?genere?numero_strade
Male1066
Female66

Le 828 strade classificate come Toponimo non hanno un nodo cpv:Person associato e non compaiono in questa query, che filtra solo i nodi con cpv:sex.

Query 2 — Lista delle strade dedicate a donne

Query 3 — Tipologia delle strade femminili

Domanda: le strade intitolate a donne sono prevalentemente "Via" o "Piazza/Piazzale"? La tipologia riflette una gerarchia simbolica nel riconoscimento pubblico.
Keyword: UNION, FILTER, DISTINCT, ORDER BY

## Query 3 — Strade dedicate a donne per tipologia (Via vs Piazza/Piazzale)
## Keywords: UNION, FILTER, DISTINCT, ORDER BY
##
## Domanda: le strade intitolate a donne sono prevalentemente
## "Via", "Piazza" o "Piazzale"? La tipologia di intitolazione
## (strada minore vs spazio pubblico) riflette un'ulteriore
## gerarchia simbolica nel riconoscimento delle donne.

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>

SELECT DISTINCT ?tipologia ?nomeVia ?nomePersona
WHERE {
  {
    ?via a clv:Street ;
         clv:hasStreetName ?nomeVia ;
         clv:isDedicatedTo ?persona .
    ?persona cpv:fullName ?nomePersona ;
             cpv:sex "Female" .
    FILTER(STRSTARTS(?nomeVia, "VIA "))
    BIND("Via" AS ?tipologia)
  }
  UNION
  {
    ?via a clv:Street ;
         clv:hasStreetName ?nomeVia ;
         clv:isDedicatedTo ?persona .
    ?persona cpv:fullName ?nomePersona ;
             cpv:sex "Female" .
    FILTER(STRSTARTS(?nomeVia, "PIAZZA ") || STRSTARTS(?nomeVia, "PIAZZALE "))
    BIND("Piazza / Piazzale" AS ?tipologia)
  }
}
ORDER BY ?tipologia ?nomePersona

Risultati aggregati:

?tipologiaConteggio
Via45
Piazza / Piazzale8

Le restanti intitolazioni femminili sono Largo, Passaggio, Rotonda, Vicolo. Solo 8 donne hanno una piazza o un piazzale a loro nome.

Query 4 — REGEX + UNION: strade "Fratelli" e donne con "Maria" nel nome

Domanda: quante strade usano "FRATELLI" nel nome (cancellando grammaticalmente la presenza femminile)? E quante donne onorate hanno "MARIA" nel nome? Le due ricerche sono combinate in un'unica query con UNION; la variabile ?tipo (ottenuta con BIND) distingue a quale dei due gruppi appartiene ogni riga.
Keyword: REGEX, UNION, FILTER, BIND, DISTINCT, ORDER BY

## Query 4 — REGEX + UNION: strade "Fratelli" e donne con "Maria" nel nome
## Una sola query che combina due ricerche tematiche con UNION.
## Keywords: REGEX, UNION, FILTER, BIND, DISTINCT, ORDER BY

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>

SELECT DISTINCT ?tipo ?nomeVia ?nomePersona
WHERE {
  {
    ## 4a — Strade con "FRATELLI": il maschile grammaticale oscura la presenza femminile
    ?via a clv:Street ;
         clv:hasStreetName ?nomeVia ;
         clv:isDedicatedTo ?persona .
    ?persona cpv:fullName ?nomePersona .
    FILTER(REGEX(?nomeVia, "FRATELLI", "i"))
    BIND("Fratelli" AS ?tipo)
  }
  UNION
  {
    ## 4b — Donne onorate con "MARIA" nel nome
    ?via a clv:Street ;
         clv:hasStreetName ?nomeVia ;
         clv:isDedicatedTo ?persona .
    ?persona cpv:fullName ?nomePersona ;
             cpv:sex "Female" .
    FILTER(REGEX(?nomePersona, "MARIA", "i"))
    BIND("Maria" AS ?tipo)
  }
}
ORDER BY ?tipo ?nomeVia

Query 5 — OPTIONAL: persone con più strade dedicate

Domanda: ci sono personaggi a cui sono dedicate più strade? OPTIONAL mostra anche le persone con una sola strada (con ?nomeVia2 non valorizzato).
Keyword: OPTIONAL, DISTINCT, FILTER, ORDER BY, LIMIT

## Query 5 — Personaggi con nome via e dati biografici opzionali
## Keywords: OPTIONAL, DISTINCT, FILTER, ORDER BY
##
## Domanda: quali persone sono onorate con più di una strada?
## OPTIONAL viene usato per cercare una seconda intitolazione:
## se esiste, viene mostrata; se non esiste, la riga appare ugualmente
## (con ?nomeVia2 = non valorizzato).
##
## Questo pattern OPTIONAL è utile anche per query future quando
## il KG verrà esteso con dati biografici (nascita, professione)
## che non saranno disponibili per tutti i personaggi.

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>

SELECT DISTINCT ?nomePersona ?genere ?nomeVia1 ?nomeVia2
WHERE {
  ?via1 a clv:Street ;
        clv:hasStreetName ?nomeVia1 ;
        clv:isDedicatedTo ?persona .
  ?persona a cpv:Person ;
           cpv:fullName ?nomePersona ;
           cpv:sex ?genere .

  OPTIONAL {
    ?via2 a clv:Street ;
          clv:hasStreetName ?nomeVia2 ;
          clv:isDedicatedTo ?persona .
    FILTER(?via2 != ?via1)
  }

  FILTER(?genere = "Female" || ?genere = "Male")
}
ORDER BY ?genere ?nomePersona
LIMIT 200

Esempi di risultati:

Ondina VallaFemaleVIA ONDINA VALLA(non valorizzato)

Laura Bassi è l'unica donna con sia una via che una piazza a lei dedicata a Bologna.

Query 6 — Dati biografici di tutte le persone onorate

Domanda: quali sono la professione, la data di nascita e la data di morte delle persone a cui Bologna ha dedicato una strada? I dati provengono dall'arricchimento biografico via Wikidata (copertura 88,7% su 1.129 persone).
Keyword: OPTIONAL, SELECT DISTINCT, FILTER, BOUND, ORDER BY, LIMIT

## Query 6 — Dati biografici: professione, data di nascita e morte per tutte le persone
## Mostra le proprietà ex: aggiunte tramite arricchimento Wikidata (88,7% copertura).
## OPTIONAL perché non tutte le persone hanno dati completi.
## Keyword: OPTIONAL, SELECT DISTINCT, WHERE, FILTER, ORDER BY, LIMIT
PREFIX clv:  <https://w3id.org/italia/onto/CLV/>
PREFIX cpv:  <https://w3id.org/italia/onto/CPV/>
PREFIX ex:   <https://w3id.org/bologna/ontology#>

SELECT DISTINCT ?nomeVia ?nomePersona ?genere ?professione ?dataNascita ?dataMorte ?luogoNascita
WHERE {
  ?strada  a clv:Street ;
           clv:hasStreetName ?nomeVia ;
           clv:isDedicatedTo ?persona .
  ?persona cpv:fullName ?nomePersona ;
           cpv:sex      ?genere .
  OPTIONAL { ?persona ex:professione   ?professione  }
  OPTIONAL { ?persona ex:dataNascita   ?dataNascita  }
  OPTIONAL { ?persona ex:dataMorte     ?dataMorte    }
  OPTIONAL { ?persona ex:luogoNascita  ?luogoNascita }
  FILTER ( BOUND(?professione) || BOUND(?dataNascita) )
}
ORDER BY ?nomePersona
LIMIT 20

Query 7 — Gender gap per quartiere

Domanda: in quali quartieri di Bologna il divario di genere è più marcato? La nuova proprietà ex:quartiere permette di disaggregare geograficamente il dato.
Keyword: DISTINCT, COUNT, FILTER, GROUP BY, ORDER BY

## Query 7 — Strade maschili e femminili per quartiere
## ex:quartiere permette di disaggregare il gender gap per zona della città.
## Keywords: DISTINCT, COUNT, FILTER, GROUP BY, ORDER BY

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>
PREFIX ex:  <https://w3id.org/bologna/ontology#>

SELECT ?quartiere ?genere
       (COUNT(DISTINCT ?via) AS ?numStrade)
WHERE {
  ?via a clv:Street ;
       clv:isDedicatedTo ?persona ;

GROUP BY ?quartiere ?genere
ORDER BY ?quartiere ?genere

Query 8 — Macro-categorie occupazionali per genere

Domanda: in quali ambiti professionali le donne sono onorate dalla toponomastica rispetto agli uomini? La proprietà ex:macroCategoriaOccupazionale permette il confronto semantico tra i due gruppi.
Keyword: OPTIONAL, DISTINCT, COUNT, FILTER, GROUP BY, ORDER BY

## Query 8 — Distribuzione delle macro-categorie occupazionali per genere
## ex:macroCategoriaOccupazionale aggrega le professioni in ambiti semantici.
## Keywords: OPTIONAL, DISTINCT, COUNT, FILTER, GROUP BY, ORDER BY

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>
PREFIX ex:  <https://w3id.org/bologna/ontology#>

Query 9 — Evoluzione storica delle intitolazioni femminili

Domanda: come è cambiato nel tempo il ritmo di intitolazione di strade a donne? La proprietà ex:dataIstituzione permette di raggruppare le intitolazioni per decennio con SUBSTR e BIND.
Keyword: BIND, SUBSTR, CONCAT, COUNT, DISTINCT, FILTER, GROUP BY, ORDER BY

## Query 9 — Intitolazioni femminili per decennio
## SUBSTR e CONCAT estraggono il decennio da ex:dataIstituzione (formato "YYYY-MM-DD").
## Keywords: BIND, SUBSTR, CONCAT, COUNT, DISTINCT, FILTER, GROUP BY, ORDER BY

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>
PREFIX ex:  <https://w3id.org/bologna/ontology#>

SELECT ?decennio
       (COUNT(DISTINCT ?via) AS ?nuoveStrade)
WHERE {
  ?via a clv:Street ;
       clv:isDedicatedTo ?persona ;
       ex:dataIstituzione ?dataIst .
  ?persona cpv:sex "Female" .
  BIND(CONCAT(SUBSTR(?dataIst, 1, 3), "0s") AS ?decennio)
}
GROUP BY ?decennio
ORDER BY ?decennio

Risultati (tutte le 66 strade femminili):

?decennio?nuoveStrade
1990s29
2000s13
2010s11
2020s13

Il picco degli anni '90 (29 strade) coincide con il grande piano di toponomastica del Comune. Il rallentamento nel decennio 2010-2019 (11 strade) è parzialmente compensato dalla ripresa nel 2020-2025 (13 strade), probabilmente influenzata dall'aumentata sensibilità pubblica sul gender gap urbano.

Query 10 — Scheda biografica completa delle donne onorate

Domanda: quali sono il quartiere, la tipologia del luogo, la professione, la macro-categoria e i dati anagrafici delle donne a cui Bologna ha dedicato una strada? Questa query combina tutte le nuove proprietà con OPTIONAL per gestire la copertura parziale.
Keyword: OPTIONAL, DISTINCT, FILTER, ORDER BY, LIMIT

## Query 10 — Scheda completa: tutte le nuove proprietà per le donne onorate
## OPTIONAL gestisce la copertura parziale: datiAnagrafici e tipologiaLuogo
## sono presenti solo per le 60 donne nel dataset "aree verdi".
## Keywords: OPTIONAL, DISTINCT, FILTER, ORDER BY, LIMIT

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>
PREFIX ex:  <https://w3id.org/bologna/ontology#>

SELECT DISTINCT
       ?nomeVia ?nomePersona ?tipologia ?quartiere
       ?professione ?categoria ?datiAnagrafici
WHERE {
  ?via a clv:Street ;
       clv:hasStreetName ?nomeVia ;
       clv:isDedicatedTo ?persona ;
       ex:quartiere ?quartiere .
  ?persona cpv:fullName ?nomePersona ;
           cpv:sex "Female" .
  OPTIONAL { ?via     ex:tipologiaLuogo               ?tipologia      }
  OPTIONAL { ?persona ex:professione                 ?professione    }
  OPTIONAL { ?persona ex:macroCategoriaOccupazionale  ?categoria      }
  OPTIONAL { ?persona ex:datiAnagrafici               ?datiAnagrafici }
}
ORDER BY ?nomePersona
LIMIT 20

Query CONSTRUCT — Generazione di triple RDF per le strade femminili

Scopo: questa query CONSTRUCT è stata usata nella pipeline di arricchimento del KG per estrarre e ricostruire il sotto-grafo delle strade intitolate a donne, pronti per essere iniettati in un nuovo file Turtle o esportati come dataset separato. A differenza delle query SELECT che restituiscono tabelle, CONSTRUCT produce direttamente triple RDF nella forma soggetto–predicato–oggetto.
Keyword: CONSTRUCT, WHERE, OPTIONAL, FILTER, LIMIT

## Query CONSTRUCT — Sotto-grafo delle strade femminili con dati biografici
## Genera triple RDF per ogni strada intitolata a una donna.
## OPTIONAL gestisce le proprietà non sempre presenti (professione, categoria).
## Keywords: CONSTRUCT, WHERE, OPTIONAL, FILTER, LIMIT

PREFIX clv: <https://w3id.org/italia/onto/CLV/>
PREFIX cpv: <https://w3id.org/italia/onto/CPV/>
PREFIX ex:  <https://w3id.org/bologna/ontology#>

CONSTRUCT {
  ?strada  a                              clv:Street ;
           clv:hasStreetName               ?nomeVia ;
           clv:isDedicatedTo               ?persona ;
           ex:quartiere                    ?quartiere .
  ?persona a                              cpv:Person ;
           cpv:fullName                    ?nomePersona ;
           cpv:sex                         "Female" ;
           ex:professione                  ?professione ;
           ex:macroCategoriaOccupazionale  ?categoria .
}
WHERE {
  ?strada  a              clv:Street ;
           clv:hasStreetName ?nomeVia ;
           clv:isDedicatedTo ?persona .
  ?persona cpv:sex      "Female" ;
           cpv:fullName ?nomePersona .
  OPTIONAL { ?strada  ex:quartiere                   ?quartiere  }
  OPTIONAL { ?persona ex:professione                 ?professione }
  OPTIONAL { ?persona ex:macroCategoriaOccupazionale  ?categoria  }
  FILTER ( cpv:sex = "Female" )
}
LIMIT 5

A differenza delle query SELECT, CONSTRUCT restituisce un grafo RDF — non una tabella. Nell'output reale le righe della tabella qui sopra sono triple serializzate in Turtle. Nella fase iniziale del progetto, la generazione del Turtle è avvenuta tramite SPARQL-Anything e la query trasforma_finale.sparql eseguita via Java. La pipeline è stata poi riscritta in Python (genera_ttl.py) per eliminare la dipendenza da Java, replicando la stessa logica CONSTRUCT senza modificare il formato del KG. La query mostrata sopra illustra questa logica di trasformazione CSV → RDF.
